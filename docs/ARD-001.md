# ARD-001: `midici` — Rust MIDI-CI / Property Exchange Responder Stack

**Status:** Draft for review · **Target:** MIDI-CI v1.2 (M2-101-UM), UMP 1.1, PE v1.1 (M2-103-UM)
**License:** MIT · **Org:** SGM-Studios (proposed) · **Primary dev target:** ALSA UMP on Bazzite, CLAP adapter second

---

## 1. Problem & Scope

MIDI 2.0 adoption is blocked on the control plane, not the data plane. UMP message types exist in Rust (`midi2` crate). What does **not** exist in Rust:

- A **MIDI-CI state machine** (Discovery, MUID lifecycle, ACK/NAK)
- A **Property Exchange responder** (chunking, Mcoded7, JSON resources, subscriptions)
- The glue that makes a **CLAP plugin's parameters auto-appear on a CI-capable controller/host** via `ChCtrlList`

**v1 scope:** Responder role only. Initiator (client) role is v2 — the API is designed so the same state machines serve both, but v1 ships responder.

**Non-goals (v1):** Profile Configuration beyond Inquiry/Reply stubs that NAK gracefully; Process Inquiry; USB descriptor work; SMF2/Clip File (separate crate later).

**Build-vs-extend decision:** Extend `midi2` (message types, SysEx7 wrappers, spec rev 1.1). Do **not** fork `midi20` (0.2.0, stale >1yr) — its CI sketch is a design reference only. We own everything above the message layer.

## 3. Layering (sans-io)

Pattern: protocol state machine with zero I/O, à la `quinn-proto`. Transports are thin adapters.

```
┌────────────────────────────────────────────────────────┐
│  Application (plugin params, device model, resources)  │
├────────────────────────────────────────────────────────┤
│  midici-responder      poll(now) / feed() / drain()    │
├──────────────────────┬─────────────────────────────────┤
│  midici-core         │  midici-pe                      │
│  Discovery, MUID,    │  Chunker/Reassembler, Mcoded7,  │
│  ACK/NAK, tx mgr     │  Resource registry, Subs        │
├──────────────────────┴─────────────────────────────────┤
│  midi2 crate (SysEx7 / UMP message types)              │
├────────────────────────────────────────────────────────┤
│  Transport adapters: ALSA UMP · CLAP events · (CoreMIDI│
│  / Windows MIDI Services later)                        │
└────────────────────────────────────────────────────────┘
```

**Core API surface (sans-io contract):**

```rust
pub struct CiEngine<R: Rng> { /* owns MUID, peers, transactions */ }

impl<R: Rng> CiEngine<R> {
    pub fn new(cfg: CiConfig, rng: R) -> Self;

    /// Feed one complete inbound SysEx7 body (F0/F7 stripped), tagged with UMP group.
    pub fn feed_sysex(&mut self, group: u8, body: &[u8]) -> Result<(), CiError>;

    /// Drive timeouts. Call at >= 10 Hz. `now` is monotonic millis.
    pub fn poll(&mut self, now: u64);

    /// Drain outbound SysEx bodies (already chunk-split to negotiated max size).
    pub fn next_outbound(&mut self) -> Option<OutboundSysex>;

    /// Drain application-facing events.
    pub fn next_event(&mut self) -> Option<CiEvent>;
}

pub enum CiEvent {
    PeerDiscovered { muid: Muid, info: DeviceIdentity, caps: CapFlags },
    PeerInvalidated { muid: Muid },
    PropertyGet   { peer: Muid, request: PeRequestId, resource: ResourceRef },
    PropertySet   { peer: Muid, request: PeRequestId, resource: ResourceRef, body: Bytes },
    SubscribeStart{ peer: Muid, resource: ResourceRef, sub: SubId },
    SubscribeEnd  { peer: Muid, sub: SubId },
    Nak           { peer: Muid, original: u8, code: NakCode },
}
```

The engine never allocates on `feed_sysex` hot paths beyond bounded, pre-reserved reassembly buffers (§6). All JSON work happens in `midici-pe` on the control thread.

## 4. Protocol Coverage (auditable checklist)

Universal SysEx frame: `F0 7E <dev id> 0D <sub-ID#2> <ci ver> <src MUID ×4> <dst MUID ×4> … F7`. Broadcast MUID `0x0FFFFFFF`. Function Block device id `0x7F`. MUID = 28-bit random.

**Management (v1 ships all):**
- `0x70` Discovery / `0x71` Reply — identity (SysEx ID, family, model, version), capability bits (Profiles `0x04`, PE `0x08`, Process Inquiry `0x10`), max SysEx size (≥128), output path ID
- `0x7D` ACK · `0x7E` Invalidate MUID · `0x7F` NAK (with status codes)
- `0x72/0x73` Endpoint (Name/ProductInstanceId) — ship; cheap and hosts query it

**Property Exchange (v1 ships all):**
- `0x30/0x31` PE Capabilities (negotiates `numSimultaneousRequests`, PE version)
- `0x34/0x35` Get / `0x36/0x37` Set (with `status`: 200/202/341/400/403/404/405/413/445 subset)
- `0x38/0x39` Subscription · `0x3F` Notify
- Encodings: ASCII, `Mcoded7`, `zlib+Mcoded7` (feature-gated)
- Chunking: `requestId` (7-bit) correlation, `numChunks`/`chunkNum` 14-bit fields, header-in-first-chunk rule

**Profiles (v1 = polite refusal):** `0x20/0x21` Inquiry/Reply reporting zero profiles; everything else NAKs with "not supported." Full profile support is v2 — DAW Ctrl / Orchestral Articulation profiles are where this goes next.

**Version handling:** advertise CI v1.2; accept v1.1 peers by masking v1.2-only features (ACK usage, Endpoint messages) per the `ci ver` byte. Never NAK on version alone.

> ⚠ **Verify against current spec revisions before freeze** — M2-101/103 field-level details above are from the 1.2/1.1 docs; the MMA has been revving (SMF2, Profiles). Pin exact doc versions in `midici-conformance/SPEC_VERSIONS.md`.

## 5. Property Resources

```rust
pub trait PropertyResource: Send {
    fn resource(&self) -> &str;                       // "DeviceInfo", "ChCtrlList", …
    fn get(&self, req: &PeQuery) -> PeResult<Payload>; // supports resId, paging offsets
    fn set(&mut self, req: &PeQuery, body: &[u8]) -> PeResult<()> {
        Err(PeStatus::NotAllowed)                      // read-only by default
    }
    fn subscribable(&self) -> bool { false }
}
```

**Provided implementations (v1):**
- `DeviceInfo` — manufacturer/family/model/version/serial
- `ResourceList` — auto-generated from the registry
- `ChCtrlList` — **the payoff.** Entries: `title`, `ctrlType` (`"cc" | "rpn" | "nrpn" | "pnac" | "pnp"`), `ctrlIndex`, `channel`, `minMax`, `default`, plus link metadata. v1 emits per-channel CC/RPN maps; per-note controller types included where the synth supports them.
- `State`/`StateList` — deferred to v2 (interacts with plugin state extension; needs design).

**`clap-autoprop` flow (killer demo):**
1. Main thread walks `clap_plugin_params` → builds `ChCtrlList` entries (param id → assigned controller, range mapped from `clap_param_info`).
2. Controller/host does Discovery → PE Get `ResourceList` → Get `ChCtrlList` → auto-maps knobs. Zero manual MIDI-learn.
3. Param changes flush through `clap_host_params` → subscription `Notify` to subscribed peers.

## 6. Threading & RT Contract (non-negotiable)

**Audio thread does exactly one thing: move bytes.**

- **CLAP adapter, RT side:** `clap_process` copies inbound SysEx event bytes into a wait-free SPSC ring (`rtrb`, fixed geometry: 64 slots × 512 B default, tunable). Pops the outbound ring and emits CLAP MIDI events. **No parsing, no JSON, no allocation, no locks, no logging.** Overflow policy: drop-with-counter (a SysEx flood must never stall audio); counter surfaced to UI/log from main thread.
- **Control thread:** host timer (`clap.timer-support`, 10 ms period) drives `engine.poll(now)`, drains rings, runs all state machines and JSON. In the standalone daemon, a plain thread with a 10 ms tick does the same.
- **Reassembly buffers:** pre-reserved, capped at 64 KiB per (peer, requestId), max 4 concurrent per peer, LRU-evicted on timeout. This is the DoS guard — a hostile "chunk 1 of 16383" must not balloon memory.
- **Buffer-size interplay:** SysEx spans `process()` blocks at any buffer size (a 4 KiB PE reply at 3 bytes/UMP-word arrives across many 128-sample blocks) — the ring + incremental reassembler handles this by construction; there is no per-block deadline. Latency budget is control-plane: discovery reply < 100 ms, PE round-trip < 50 ms on loopback. Sample rate is irrelevant to CI except that it bounds how much SysEx a block can carry; denormals/SIMD are non-issues here (no DSP) — the RT cost is two ring memcpys.
- **Verification:** `assert_no_alloc` wraps the RT path in debug; loom or miri pass on the ring wrapper.

## 7. Failure Modes

| Failure | Detection | Mitigation |
|---|---|---|
| MUID collision | Discovery reply w/ our MUID from another node; Invalidate MUID | Regenerate MUID, re-announce; injected RNG makes this testable |
| Chunk flood / memory DoS | Reassembly cap breach | 64 KiB + 4-tx per-peer caps, evict + NAK 413 |
| Interleaved transactions | `requestId` collision from same peer | Per-(peer, requestId) keying; excess → NAK 445 (busy) |
| Peer lies about max SysEx | Outbound chunk > negotiated size | Chunker hard-clamps to negotiated min(theirs, ours) |
| Malformed PE JSON | serde error | NAK 400; depth/size limits on parser; never panic |
| v1.1 peer meets v1.2 msg | `ci ver` byte | Feature-mask per peer, never version-NAK |
| RT ring overflow | drop counter > 0 | Counter + rate telemetry; size tunable; control-plane loss is recoverable (peer retries) |
| Subscription leak | Peer vanishes w/o unsubscribe | Subs tied to MUID liveness; Invalidate/timeout reaps them |
| Stalled multi-chunk tx | Inactivity timer | 3 s per-tx timeout → NAK 341, buffer reclaim |

## 8. Test Strategy & Eval Criteria

**Test checklist:**
1. **Property tests** (proptest): Mcoded7 round-trip; chunk-split/reassemble round-trip at every negotiated size 128–4096; MUID lifecycle model test.
2. **Fuzzing** (cargo-fuzz): SysEx framing, CI header parse, PE JSON header, reassembler. Gate: 10⁸ execs clean before 0.1.
3. **Golden transcripts:** captured Discovery/PE exchanges checked into `midici-conformance` (sources: MIDI 2.0 Workbench, Wireshark UMP dissector pcaps from midi2.dev tooling). Replayed byte-exact in CI.
4. **RT audit:** `assert_no_alloc` + miri on ring path; 24 h soak of discovery churn (peer appear/vanish loop) with zero growth (heaptrack).
5. **Interop matrix (definition of done for 0.1):**
   - MIDI 2.0 Workbench: full Discovery + PE Get suite passes
   - Bitwig on Linux (only Linux DAW with usable UMP today): discovers responder, reads DeviceInfo
   - Windows MIDI Services console tooling: enumerates + Endpoint Name reads
   - Hardware (when available — Keystage-class PE controller): ChCtrlList auto-map demo

**Perf gates:** loopback Discovery < 100 ms; 4 KiB PE Get < 50 ms; RT path ≤ 2 memcpys/event, zero alloc.
